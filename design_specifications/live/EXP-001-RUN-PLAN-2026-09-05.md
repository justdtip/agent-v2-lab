## 0. Preflight regeneration (narrow, no arm inputs)

```
uv run agent-pipeline preflight --model qwen25-coder-3b
uv run agent-pipeline preflight --model qwen35-4b
```

Checks after each, before the next runs:

- `schema_version` is 3 and `passed` is true.
- `model_name` and `hf_id` match the registry.
- `training_footprint` is **present**, with `skipped` true, `passed` true, and a `skip_reason`
  naming the missing row count. An absent block fails this check (the Chief's condition).
- `snapshot_revision` is recorded; both revisions go in the commit message (the Chief's second
  condition).
- `require_preflight` then passes for both specs where it rejects today.

The commit carries the calibration code, the three registry configs that gained the
`memory.budget_gib` cap, and both regenerated artifacts, together, per R37.

## 1 and 2. The 3B arms (comparability, B1/R35)

```
uv run agent-v2-jspace-sweep --model qwen25-coder-3b --policy base \
  --jvp-method finite_difference \
  --output outputs/probes/jspace-qwen25-coder-3b-base-2026-09-05

```

Run 1 is the comparator; run 2 gives continuity with the recorded 3B table, which §5 supersedes

## 3. The 4B sweep

```
uv run agent-v2-jspace-sweep --model qwen35-4b --policy base \
  --output outputs/probes/jspace-qwen35-4b-base-2026-09-05
```

`--jvp-method` is **omitted** so the run takes the method the regenerated preflight recorded.
Before running, read the artifact's `jvp` block. If it records anything other than
`finite_difference`, **the lane stops** — but not for the reason an earlier draft of this plan
gave, which had the argument backwards (Head of Interpretability, 2026-09-05). Passing the flag
would make the arms *match*, not diverge; the 3B arms are pinned, so a floating 4B method is the
confound B1 exists to remove. The reason to stop is different: the 4B recorded
`finite_difference` because forward mode failed on the hybrid and preflight falls back. A
regenerated artifact recording `forward` is therefore not an estimator fact, it is evidence that
the calibration slice changed how the JVP probe behaves, and that is worth a look before any run.

The estimator facts behind this check — why forward mode fails on the hybrid, what the pinned
probe layer is, and what a changed reading would mean — are recorded by the Head of
Interpretability in EXP-001 §5, beside the preflight gate. This plan is a lane document and
does not restate them.

**Resolution rule, so the lane is not blocked on a person at two in the morning.** Look at why
the recorded method changed. If the change is benign, pin the 4B to `finite_difference` as well
and record in the conformance block that the method was **chosen for comparability under R35**
rather than taken from the preflight. Finite differences stay valid wherever forward works — two
evaluations of the tail is a weaker requirement than autodiff — so pinning costs only the second
tail pass. Matching arms is the load-bearing requirement; §3.2's "the method the preflight
recorded" exists to keep the run on a method the model supports, not to let the method float
between arms.

Layers are left to the registry default, which resolves to the nine of §3.5 (5, 11, 12, 16, 20,
21, 27, 28, 32) with the kind-matched partners.
