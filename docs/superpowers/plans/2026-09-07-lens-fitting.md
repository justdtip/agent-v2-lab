## Task 1: Corpus builder (requirements 3.1 and 10)

Ownership: src/local_llm_lab/pipeline/lens_fitting/__init__.py, corpus.py, scripts/lens_corpus.py, tests/test_lens_corpus.py. Do not change the prototype fitter, the runner, live_lens files or the registry.

Build an immutable, hash-bound corpus manifest plus a sequence JSONL artifact. The shared interface is read_corpus(manifest_path), yielding sequence dictionaries with index, source, task_id (where applicable), step_index, split ('fit' or 'held'), ids (list[int]), spans (one string per ID), n_prompt, and domain. Include rendered prompt/text in the JSONL if useful to audit alignment; never store model activations. A manifest includes schema_version, domain, model hf ID, source paths and SHA256s, tokenizer/template identity, sequences path and SHA256, sequence counts and tokens by split/span, dropped rows, and fixed held-out/pilot-exclusion rules. read_corpus validates the hash and row invariants before returning records.

Agentic inputs are evaluation JSON files from train/train1/train2 only. Every step (including a final unparsed raw step) becomes the runner prompt plus that step's raw output. Render using SYSTEM_PROMPT, canonical assistant_message/tool_message, build_prompt with DEFAULT_KEEP_LAST (two), and the generation suffix. Append valid prior actions/observations exactly as run_task does and stop at finish or parse failure. Preserve the model's own raw completion in the current sequence. Assign a global source-step index in source/trajectory/step order BEFORE length filtering, with every fifth index (one-based 5,10,...) held out. Drop over-cap sequences and keep their index/source/count in the manifest so dropping cannot move membership. The API takes max_tokens explicitly; the script supplies the specification's 2048-token corpus cap (a data-budget constant, not an architecture dimension).

Tokenize the entire prompt-plus-raw text once with the model tokenizer's BOS policy. Tokenization offsets must partition every token into exactly one span: system, task, observation, note, call, template, chat; prose uses chat as the shared prose-content span with domain='prose'. Reuse the existing atlas span-labelling semantics for canonical messages, but do not import scripts that mutate sys.path. Token labels straddling semantic boundaries become template. A raw output's fenced call is call; preceding material is note. Fail if alignment cannot be established. Preserve actual windowed messages, not unwindowed tool results, when locating prompt spans.

Require source trajectory IDs to be training-split IDs; fail closed on test/validation/pilot IDs or mixed model declarations. The pilot exclusion must be testable, not just descriptive. Record source content hashes; reject duplicate source paths or duplicate trajectory identities across inputs. Keep source ordering explicit in manifest. Synthetic tests can supply minimal matching training IDs and a fake offset tokenizer.

Prose inputs are text files chunked into nonoverlapping 1024-token windows, with discarded trailing tokens counted and the same every-fifth-sequence split. A CLI option downloads the authorised Hugging Face dataset once, pinned to a resolved dataset revision, stores validation text and a download descriptor under a caller-provided data directory, and then builds the ordinary text corpus. Reuse only a hash-verified existing download. Never fetch train or test splits. Tokenizer loading fetches only tokenizer/config assets, never checkpoint weights or load_policy. Record local tokenizer-file hashes and template identity. Do not execute any network download during unit tests.

Use exclusive creation/immutable outputs and allow_pickle=False where applicable. Tests name requirements sections in docstrings, first demonstrate the missing behavior, then verify: prompt equality against build_prompt; exact span coverage; hidden-observation labels; raw completion boundary/BOS handling; fifth-step membership unaffected by a dropped row; no pilot/test leakage; input or sequence corruption; prose chunk/tail accounting; download boundary restricted to authorised configuration/split and revision. Run focused tests and repository rules with PYTHONPATH=src using the existing .venv. Commit explicit owned files after self-review. Do not spawn subagents or load a checkpoint.

## Task 3: Jacobian measurement and map validation (3.3, 3.6)

Ownership: lens_fitting/jacobian.py, validation.py, tests/test_lens_jacobian.py; extend only own fit CLI after Task 2. Build a pre-norm tail from view blocks, never ArchitectureView.tail. Full basis, float32 central finite differences, cached native prefix states cloned or batch-broadcast without mutation. Validate cached single-position derivatives against full-sequence uncached finite differences on 16 directions at three layers before fitting. Derivative direction/batch and epsilon conventions must be explicit and equal between the reference and candidate. Tiny linear tails provide independent analytic Jacobians.

Sample fit positions deterministically by span with equal allocation, persist seeds and selected source/position identities before execution. At least 150 per layer; convergence diagnostics every ten samples, two consecutive relative Frobenius changes below 0.002, no decision below 100 and no accepted fit below 150, ceiling 400. Record complete curves and reasons. Benchmark batch8 first, then cloned/broadcast choices up to64 under declared memory limits. Before every long fit, measure projected time per layer; a cost above25 minutes requires the Director's choice before all-layer execution. Do not substitute fewer basis directions. Validation uses held-out positions and32 random unit directions with predeclared bounds; existing response_agreement and layer_verdict own verdicts. Concept/output hooks cannot request refits.
